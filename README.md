# パン屋の販売予測デモ

このフォルダーの `start.cmd` をダブルクリックすると、専用の仮想環境から発表画面が開きます。モデルと販売データを準備したこのPCでは、当日はオフラインで操作できます。

## 発表での操作

1. **「セール日を試す（模擬データ）」**で、入力に使うデータにチェックを入れます。予測したい商品の販売履歴は必須です。チェックをすべて入れ、**「推論」**を押すと、A・B・Cの中央値が同じグラフに出ます。その下の表で、各条件に渡した入力と予定日の予測個数を確認できます。
2. **「今後のセール日」**を11/4（水）から11/6（金）に変更します。「推論」を押すまでは、前回のグラフと表を表示します。もう一度押すと、新しい予定で再計算し、前回のCの予測線と日別の増減を重ねます。比較する2回の実行では、過去の情報のチェックを同じにします。
3. **「店舗の実績と比べる（実データ）」**を選び、「推論」を押します。フランスのパン屋で販売されたトラディショナル・バゲットについて、28日間の予測と実際の日別販売数を重ねます。表には、観測値がある27日間の平均絶対誤差（MAE）を個/日で表示します。

Aは対象商品の販売履歴のみで毎回計算します。Bはチェックした過去の補助情報を1つ以上使うときに、Cはセールのチェックが入っているときに計算します。セールだけを追加した場合はAとCを比較できます。「セールなし」を選んだCには過去のセール記録と、未来の全日が非開催という予定を渡します。最後に追加した条件の予測帯（P10〜P90）は初期表示がオンで、チェックを外すと非表示になります。

予測グラフの下段には、他のパンの売れ行きと来店者数（実店舗では会計件数）の直近28日間を、予測と共通の日付軸で表示します。各段のラベルに入力を使った条件を示し、未使用の系列は灰色で表示します。セール日の段では過去の開催日を白抜きのひし形、今回の予定を塗りつぶしのひし形で示します。予定を変更して推論すると、比較対象の前回の予定は白抜きの丸で表示します。

モデルは最初の「推論」でメモリに読み込まれます。発表前に一度実行してからブラウザを再読み込みすると、モデルが温まったまま未計算の画面から始められます。チェックの変更や表示の切り替えではモデルを呼びません。模擬データの標準条件には「実行方法」から選ぶ事前計算の再生もあり、ボタン名を「保存結果を表示」に切り替えます。

## データの出典と評価方法

**セール実演**では `data/history.csv` の256日分を使います。週末の需要、客足の変化、曜日を固定しない過去のセールを含む、乱数シード1126の教材用データです。予測対象は食パン、過去の補助情報はロールパン・バゲット・来店者数、未来に使える情報は予定されたセール日です。自動生成した将来値は精度評価に使いません。

**実店舗の評価**では、Matthieu Gimbert公開のフランスのベーカリー取引データ（2021/1/2〜2022/9/30、234,005明細）を使用します。`prepare_real.py` が元CSVのSHA-256を確認し、商品別の日次純販売数と日別の会計件数を作ります。数量は負の返品を含めて合算します。会計件数は異なるレシート番号の数です。対象商品は `TRADITIONAL BAGUETTE`、補助商品は `CROISSANT` と `PAIN AU CHOCOLAT` です。元データに販促予定表がないため、実店舗ではA・Bを比較します。[French bakery daily sales（配布元）](https://www.kaggle.com/datasets/matthieugimbert/french-bakery-daily-sales)

| 区間 | 使用方法 |
|---|---|
| 2021/12/21〜2022/9/2（256日） | 予測の入力。全店の記録がない11日を欠測とし、モデルに渡すときだけ入力期間内で線形補間します。店舗の取引記録があり、対象商品が記録されなかった日は0個とします。 |
| 2022/9/3〜9/30（28日） | 評価用。モデルに渡す入力は予測開始の前日までで固定します。9/19は店舗全体の記録がないため欠測とし、残る27日の実測値で評価します。 |

## 別のPCで再現する

Windows・Python 3.11を想定しています。初回のパッケージ、重み、実データの取得にネットワーク接続を使います。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-windows-cpu.lock
.\.venv\Scripts\python.exe download_model.py
.\.venv\Scripts\python.exe prepare_real.py
.\start.cmd
```

すでにKaggleのZIPを取得している場合は、`prepare_real.py "ダウンロードしたZIPのパス"` でも同じ日次ファイルを作成できます。VS Codeではこのフォルダーを開き、Pythonインタープリターに `.venv\Scripts\python.exe` を選びます。

模擬データの履歴と標準29通りの保存結果を作り直す場合は、順番に以下を実行します。

```powershell
.\.venv\Scripts\python.exe generate_data.py
.\.venv\Scripts\python.exe precompute.py --device cpu
```

Ryzen 5 5600Uでの条件C単体は、モデル読み込み後の実測中央値0.55秒です。発表画面の「CPU推論完了」は、押すたびに選択条件全体を処理した時間を表示します。CUDA版PyTorchのあるGPU機では、模擬データの事前計算に `--device cuda` を指定できます。

Gitにはコード、固定した依存バージョン、生成した模擬履歴、模擬データでの保存結果が含められます。`.venv/`、`.models/`、実店舗のローカル集計ファイルは除外しています。配布されているTimesFM-3の重みには非商用・非本番用途のライセンスが適用されます。[TimesFM公式実装](https://github.com/google-research/timesfm)・[使用した重み](https://huggingface.co/google/timesfm-3.0-pytorch/tree/43046b85ec22d584a13f8098c2ed39c889e129c2)
